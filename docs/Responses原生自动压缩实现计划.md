# Responses 原生自动压缩实现计划

## 已确认要求

- 仅 Responses 接口支持，按模型显式配置，默认关闭。
- 不实现自动能力探测，不额外发送探测请求。上游明确拒绝配置时给出错误提示。
- 本次仅实现功能、测试和文档，不修改用户 config.toml，也不替 nd-gpt-astra 开启。
- 复用现有协议兼容工作，保留全部未提交修改，禁止 Git 还原及修改 Cargo 缓存。
- 计划模式仅能写本文件；批准退出后，业务代码修改前首先将本计划保存至 docs/Responses原生自动压缩实现计划.md，不自动提交。

## 1. 配置与请求链路

新增模型级可选正整数 responses_compact_threshold。省略为关闭，配置值为触发 token 数。示例：

```toml
[model.example]
api_backend = "responses"
responses_compact_threshold = 200000
```

零、负数、错误类型走现有配置告警；非 Responses 配置该字段时告警并禁用。最终阈值必须小于当前有效上下文窗口，检查包括窗口覆盖后的结果。

贯通 agent/config.rs 的 ModelEntryConfig、ConfigModelOverride、ModelInfo，sampling-types::SamplingConfig、sampler::SamplerConfig、spawn/model_switch/sampler_turn 与 subagent 构造。临时发现模型默认关闭，不借用来源模型能力。子代理按实际选中模型配置；已有轮次和 resume 保持已有快照语义。

在 sampler/client.rs 流式和非流式 Responses 请求使用共同 helper 写入 context_management: [{type:"compaction",compact_threshold:N}]。其他协议及未启用请求省略整个字段。辅助分类和客户端摘要请求保持自己的策略，避免递归触发原生压缩。

## 2. 来源隔离与请求历史裁剪

原生压缩只缩短发送给上游的请求历史，不主动替换本地会话历史。保存加密输出的来源标识：实际请求模型、规范化连接地址和认证身份指纹；不保存或打印明文密钥。标识从实际发送认证快照生成并绑定响应，客户端覆盖内部保留字段，禁止信任上游伪造值。

扩展 AssistantItem 原始输出旁的可选来源数据，旧会话缺省兼容。仅成功接纳的完整响应可产生可用压缩点；失败、取消和未终止流不能提交新压缩点。

扩展 patch_responses_input：

1. 验证通用历史与原始快照一致，并遵守现有工具配对修复和删除规则。
2. 从同来源输出中选择最新有效 compaction，精确定位到 output 数组内部。
3. 保留必要的当前系统指令、该压缩项以及之后的消息和工具交互，裁掉已覆盖前缀。
4. 验证调用/结果配对；边界不安全时放弃该压缩点，使用现有保留历史。
5. 来源不匹配、无来源旧数据、历史修改导致失效时，过滤加密压缩项并回退通用历史。

关闭配置时回到客户端策略并使用通用历史；模型/连接/认证变化不能发送旧来源压缩项。检查 rewind、resume、fork、手动压缩和图片删除等路径，避免旧快照恢复已清理数据。现有 retained-history 清理仍有效，不承诺恢复此前已经清理的原文。

## 3. 与客户端压缩协调

建立统一有效策略：显式开启且协议为 Responses 时，由服务端负责常规阈值压缩，跳过现有 check_auto_compact_needed 百分比触发及 should_prefire_two_pass 后台预压缩，处理残留预压缩任务。

保留手动 /compact、实际请求过大时的客户端容量保护，以及现有上下文溢出恢复。容量保护使用实际准备发送的历史范围，不能只看完整本地历史。切模型后恢复目标模型的策略并重新评估容量。

上游拒绝 context_management 时明确报错，不自动探测、缓存能力状态或静默关闭。鉴权、限流及网络错误沿用已有分类；不对已产生输出或执行工具的请求盲目重放。加密项被拒绝时明确提示调整配置或手动压缩，保持有界错误恢复。

## 4. 上下文用量

保留上游 input/output token 和费用的原始累计计量。用于上下文显示和容量保护的数值按有效请求计算，避免重复记录将其覆盖为完整历史或压缩过程累计用量。

优先使用明确的压缩后 context_details；缺少时使用保守估计，并在现有展示机制中标识估计。加密内容长度不作为精确 token 数。实现需核对 turn.rs 与 sampler_turn.rs 两处 usage 写入及 chat-state 的新增内容估算。

本次不增加百分比进度条；保留压缩活动事件兼容，不承诺上游会发送实时进度。

## 5. 测试与文档

使用 tools/windows-protoc/test-release.ps1 定向验证配置、请求构造、历史和策略：

- 默认关闭、正整数校验、非 Responses 禁用；流式/非流式一致。
- 单次和连续多次压缩，消息/工具与压缩项交错顺序，系统指令保留，边界配对安全。
- 模型、连接、认证变化不泄漏旧加密项；缺来源旧会话安全回退。
- 手动压缩、rewind、恢复、fork、图片删除和上下文裁剪不复活旧快照。
- 普通阈值与预压缩不抢先触发；硬限额保护继续有效。
- 上下文估算与累计用量分离，取消/错误不提交压缩点。
