# GPT Fast 模式实现计划

## 需求与行为

- 模型配置新增 `fast_mode = false`，缺省关闭；`true` 使该模型在新会话中默认开启。
- 仅 Responses 后端使用 Fast。开启时请求携带 `service_tier: "priority"`（OpenAI Fast 的兼容值），关闭时省略该字段，沿用上游默认处理。
- `/fast` 切换当前会话、当前模型的状态；`/fast on`、`/fast off` 显式设置；`/fast status` 查询。
- 会话覆盖不写配置，同一会话切换模型后返回仍保留覆盖，不影响其他会话。
- 非 Responses 模型查询显示不支持，开启/关闭/切换操作返回明确提示。
- 轮次开始时固定 Fast 状态，执行中的轮次保持原状态，开关在下一轮生效。

## 实现范围

1. 模型配置解析、默认值、序列化与采样配置完整传递 `fast_mode`。
2. Responses 流式和非流式请求统一注入服务等级；Chat Completions 和 Messages 保持原请求结构。
3. 会话 actor 提供 Fast 状态和操作，通过 `x.ai/session/fast_mode` 扩展方法暴露。
4. 终端命令菜单、参数解析、状态反馈接入 `/fast`，维护 README 与相关用户指南。

## 验证

- 使用 Windows Release 定向测试脚本验证配置解析、请求载荷、会话隔离、模型切换、轮次快照、命令解析。
- 复用已编译测试程序运行多个过滤条件。
- 视构建情况运行本地假上游端到端验证，不使用真实凭据或付费上游。
- 本次为终端应用功能；以协议和终端对应测试验证交互。
