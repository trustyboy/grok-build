# 模型按需发现与视觉开关实现计划

## 目标与边界

- `/model <模型ID>` 本地未命中时，显式异步优先查询当前会话所用上游的 `/models`；未命中或查询失败后回退其他已配置且可选的上游，按配置顺序选择首个精确命中来源并切换。多个来源命中时自动采用首个，全部未命中保留当前模型。扩展细节见 `跨上游模型发现实现计划.md`。
- 新发现模型默认 `supports_vision=false`、`context_window=256000`；不继承模板的思考级别、变体路由、后端搜索等能力。
- 新增 `/support_vision` 查询状态，`/support_vision on|off` 修改当前会话、当前模型的视觉输入设置。切走再切回来保留本会话选择，不影响其他会话，不写用户配置。
- 运行时发现不修改 `[models].default` 或 `[model.*]`。退出后台进程后临时目录失效；恢复找不到的临时模型时显式提示，不伪装成已恢复。
- 现有已配置模型和内部同步解析保持原有行为。修改仅覆盖显式命令入口及其必要的会话状态和鉴权链路。

## 发现与注册

1. 新增独立的异步发现/切换请求，携带会话 ID、目标模型 ID 和预期当前模型 ID。
2. 本地已有但不可选、被禁用或被隐藏的条目不能通过远程发现重新暴露。
3. 优先查询当前连接，必要时回退其他已配置且可选的连接：每个来源的地址选择、认证方式、请求头、环境头、查询参数和客户端证书遵守自身推理配置；凭据提供者在需要时异步刷新。认证失败不得降级为登录凭据。
4. 列表请求设置超时、响应体上限、重定向限制；远端仅提供目标 ID，不采纳其地址、凭据和请求头字段。普通 OpenAI 兼容列表按 `data[].id` 精确匹配。
5. 将连接来源引用与运行时能力分别保存；源配置变化后重新解析，来源失效则失败关闭。运行时条目独立于远程目录缓存，配置/目录刷新不能无声丢弃它。
6. 注册时重新执行目标模型的允许/禁用/隐藏规则；相同 wire ID 已有不同路由时拒绝歧义。
7. 网络等待期间不持有会话或目录锁；提交前重新验证会话、来源和权限。切换成功才向客户端报告成功。
8. 保留 `resolve_model_id()` 的同步纯解析性质，以及 `SetDefaultModel` 对已知目录 ID 的校验。临时条目始终走不保存默认值的切换路径。

## 网络访问策略

- 用户显式查询自定义上游与后台 xAI 设置获取分离：用户级 `remote_fetch=false` 不启动任何后台获取，显式发现仅访问当前连接和其他本地已配置且可选的连接。
- 管理/组织层的禁止远程获取策略仍然优先，禁止通过新命令绕过。
- 首版不添加持久模型列表缓存，避免跨凭据、跨来源复用；需要时仅复用现有 HTTP 客户端基础设施。

## 鉴权一致性

- 每轮鉴权、凭据刷新及相关辅助路径必须能解析运行时条目，而不是仅从磁盘配置寻找新模型。
- 运行时模型不能因磁盘没有同名条目被误判为使用登录会话认证。
- 来源删除、权限收紧或认证配置不可用时返回明确错误；不得静默使用全局默认模型或另一套密钥。
- 不把临时 token 或密钥写入计划、日志、客户端响应或新增缓存。

## 视觉状态

- 当前会话的模型和手动覆盖值是视觉判断的来源，取消 hook 和采样重建对共享 `current_model_id` 的依赖。
- hook 与 sampler 在下一轮使用同一有效视觉值；已在运行的轮次不半途改变。
- 关闭视觉时保留图片附件存盘和文本路径，继续支持 vision-bridge；该插件仅引导模型调用识图工具，不保证识图成功。
- 返回明确的视觉状态供命令显示，不把原生视觉关闭等同于禁止附件。
- 状态覆盖仅驻留当前会话；恢复会话回到模型定义的默认能力，明确不承诺跨进程持久保存。

## 接口约定

- `x.ai/models/discover_and_switch`：`{sessionId, modelId, expectedModelId}`；成功返回 `ExtMethodResult` 的 `result: {models: SessionModelState}`。
- `x.ai/session/support_vision`：`{sessionId, enabled?: bool, expectedModelId?: string}`；无 enabled 时查询；成功返回 `result: {modelId: string, enabled: bool}`。
- 运行时模型的 ACP 元数据带 `runtimeDiscovered=true`，防止后续选择时被当作可持久化默认模型。
- 界面必须等待服务端成功后更新动态模型选择；错误保留原选择并显示原因。

## 分工与落点

- Shell 模型管理器：运行时条目、源引用、权限及重建、鉴权解析。
- Shell 异步处理器：发现、请求认证和切换提交。
- Session actor：会话视觉覆盖与每轮有效值、视觉扩展请求。
- Pager：发现命令 action/effect/result，视觉命令注册与请求，运行时条目不保存默认模型。

## 验证

优先本地 mock 和针对性 Release 测试：

- 查询成功/未命中/401/超时/恶意路由字段；只向指定来源发送凭据。
- 新条目默认能力、思考变体清空、权限过滤、热重载存活或明确失效。
- 动态模型第二轮仍使用正确凭据，provider/认证来源不丢失。
- 双会话视觉隔离，切换模型后覆盖保留，插件与发出的图片内容一致。
- 未知模型发现失败不改界面当前模型或默认配置；运行时模型再次选择不落盘。
- 无参数视觉命令只查询，on/off 校验与错误路径。

Windows 正式构建仅使用 `& .\tools\windows-protoc\build-release.ps1`；所有 Rust 编译验证使用 Release。计划文档不主动提交 Git。
