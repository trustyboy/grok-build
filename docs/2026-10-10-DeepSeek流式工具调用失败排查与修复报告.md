# DeepSeek 流式工具调用失败排查与修复报告

## 一、结论

Grok 在合并 Chat Completions 流式工具调用时，无条件接受已出现的 `function.name` 字段。当前 DeepSeek 连接的首片段返回有效工具名，后续参数片段返回 `name: ""`；空字符串覆盖了已有名称，最终工具注册表按空名称查找并报错。

本次修复让空名称更新成为无操作，保留已有名称，同时继续拼接参数；下游流式事件也跳过空名称更新。修复已通过 Release 定向测试、正式 Windows Release 构建和同一 DeepSeek 网关的端到端验证。

## 四、根因与影响范围

### 4.1 源码位置

```text
crates/codegen/xai-grok-sampler/src/stream/chat_completions.rs
```

`stream_chat_completions` 按调用 `index` 维护 ID、名称和参数缓冲区。原名称合并逻辑为：

```rust
if let Some(name) = func.name {
    entry.1 = name.clone();
    name_for_event = Some(name);
}
```

空字符串被反序列化为 `Some("")`，因此会进入赋值分支。工具名被清空后，最终响应和下游流式事件都携带了错误的名称状态。

参数采用追加方式，调用 ID 在本次响应中仅于首片段提供，因此日志表现为“ID 与参数完整、名称为空”。

### 4.2 为什么其他连接可能正常

| 后续名称字段 | 原处理行为 |
| --- | --- |
| 缺省 | 保留已有名称 |
| `null` | 反序列化为 `None`，保留已有名称 |
| 再次返回同一个有效名称 | 覆盖为同名，继续正常执行 |
| `""` | 覆盖为空，后续查找工具失败 |

不同上游与网关可能采用不同的字段序列化形式。此次已验证当前 DeepSeek／CPA 连接触发空字符串分支；其他模型连接未逐一抓取响应。

证据支持“特定响应格式与客户端合并逻辑的兼容缺陷”。空字符串具体来自模型服务还是 CPA 网关转换，仍需对比网关上下游响应。DeepSeek 官方直连与其他部署的格式也应分别验证。

## 五、网络资料核实

### 5.1 DeepSeek 官方文档

官方 Chat Completions 文档说明：每个工具调用的首片段携带 `id`、`type` 和 `function` 字段，后续片段传输函数参数。

> The first chunk of each tool call carries the `id`, `type` and `function` fields; subsequent chunks only carry the function arguments.

这要求客户端保存调用信息并累计参数。文档未统一保证后续名称字段采用缺省、`null` 或空字符串中的哪种形式。

来源：<https://api-docs.deepseek.com/api/create-chat-completion>

### 5.2 相同空字符串问题的公开报告

DeepSeek 官方仓库的社区讨论 #3807，发表于 2026-08-21，标题为“llm-deepseek loses tool name when later deltas repeat an empty name”。报告明确描述部分兼容网关首片段发送有效名称、后续片段发送 `name: ""`，客户端覆盖后报 `UNKNOWN_TOOL`，与本次故障机制一致。

来源：<https://github.com/deepseek-ai/deepseek-harness/discussions/3807>

讨论 #161 的 2026-08-14 回复中，用户报告通过 DeepSeek-V4-Flash 的流式响应复现了后续 `function.name` 为空字符串的问题。

来源：<https://github.com/deepseek-ai/deepseek-harness/discussions/161#discussioncomment-18010525>

上述内容属于公开用户复现记录。

### 5.3 官方 SDK 的兼容处理

直接核对 OpenAI Node SDK `v6.26.0`，其工具名称更新使用非空判断，参数继续追加：

```typescript
if (fn?.name) tool_call.function!.name = fn.name;
if (fn?.arguments) {
  tool_call.function!.arguments += fn.arguments;
}
```

来源：<https://github.com/openai/openai-node/blob/v6.26.0/src/lib/ChatCompletionStream.ts#L518-L530>

OpenAI 官方工具调用文档也说明 `id`、`function.name`、`type` 等字段通常仅在首个片段设置：

<https://developers.openai.com/api/docs/guides/function-calling>

## 六、修复内容

生产代码增加非空过滤：

```rust
if let Some(name) = func.name.filter(|name| !name.is_empty()) {
    entry.1 = name.clone();
    name_for_event = Some(name);
}
```

行为如下：

- 空名称、`null`、缺省名称均保留已有名称。
- 空名称不会作为更新继续发送给下游流式消费者。
- 参数片段仍按原逻辑追加。
- 支持工具名延迟到达及后续非空名称更新。
- 流始终缺少有效名称时保持空值，由现有工具查找路径报告错误。

本次范围为名称合并；工具调用 ID 的合并规则保持原实现。

同文件新增两个针对性回归测试：

1. `tool_call_stream_preserves_names_across_empty_continuations`：两个调用交错到达，覆盖空字符串、`null`、缺省名称，并核对流式事件、最终名称、调用 ID 和完整参数。
2. `tool_call_stream_accepts_late_names_without_inventing_missing_names`：覆盖名称延迟到达、后续非空更新以及始终缺少名称的边界。

维护说明同步写入根目录 `AGENTS.md` 和 `README.md`，便于后续合并上游时保留兼容处理。
