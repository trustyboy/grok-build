# 子代理模型配置与临时切换实现计划

## Alex，建议实现以下行为

全局配置新增统一默认模型和推理强度：

```toml
[subagent]
model = "nd-gpt-astra"
reasoning_effort = "high"
```

两个字段均可独立省略。无其他模型规则时继承主会话当前模型；省略 effort 时沿用现有规则：继承路径保留父会话当前值，其他模型采用自身默认值。角色、persona、按类型与 agent 定义继续按优先级生效。

正式名称统一为 `[subagent]` 及 `models/roles/personas/toggle` 子表、`/subagent-model`、`x.ai/session/subagent_model`。旧 `[subagents]` 兼容读取，同键单数优先、旧表独有键保留；旧命令 `/subagents-model` 和旧 endpoint `x.ai/session/subagents_model` 保留别名。内部复数类型、集合、目录和历史文件名不改。

在已有主模型配置中新增：

```toml
[model.cpa-deepseek-v4-flash]
subagent_model = "nd-gpt-astra"
```

该字段仅选择 model，不新增 effort。按父会话实时模型目录键读取；省略/空白回退全局，无效目标告警回退全局。临时发现模型自身未配置时回退全局，不借用上游来源模型字段。

也支持只设置推理强度：

```toml
[subagent]
reasoning_effort = "high"
```

无其他模型规则时，此配置让普通子代理跟随主模型，并使用配置的推理强度。实际应用前检查目标模型支持的档位。

| 命令 | 行为 |
| --- | --- |
| `/subagent-model` 或 `/subagent-model status` | 查询默认模型、来源、配置有效性 |
| `/subagent-model <模型ID或名称> [window] [effort]` | 临时指定模型、可选上下文窗口与推理强度；未知单个 ID 通过上游发现 |
| `/subagent-model inherit` | 临时设置为跟随主会话当前模型 |
| `/subagent-model reset` | 清除临时覆盖，恢复配置规则 |

临时选择仅保存在当前会话内存，命令完成后新建的子代理生效。已经启动的子代理继续使用启动时模型；恢复子代理继续使用其原模型。

## 现状与方案

- `config/mod.rs::SubagentsConfig` 已支持 `[subagent.models]`，键为子代理类型，例如 `general-purpose`、`explore`。
- `agent/config.rs::resolve_subagents` 传递配置；`agent/mvp_agent/subagent_spawn.rs` 为启动创建父会话快照。
- `agent/subagent/mod.rs` 及 `handle_request.rs` 处理模型选择及子代理生命周期。普通继承读取父会话真实采样配置。
- 前端已有模型命令的请求屏障、会话归属检查和 ACP 扩展调用模式，可以复用。

推荐使用统一字段和会话级三态覆盖。其他方案包括为每种类型填写 `[subagent.models]`，或在映射中增加通配键；统一字段更直接地表达默认模型，保留按类型配置的兼容性。

工作区已有 Fast 模式等未提交修改，实施时在现有内容上做局部修改；代码与文档由用户决定是否提交。

## 模型选择优先级

普通新建子代理从高到低：

1. 单次启动显式指定的模型。
2. 当前父会话 `/subagent-model` 临时选择：指定模型或直接继承父模型。
3. 已有角色或 persona 的模型默认值。
4. 已有 `[subagent.models]` 按类型指定。
5. 当前主模型 `[model.<id>] subagent_model`。
6. `[subagent] model` 统一默认值。
7. agent 定义文件中的模型。
8. 父会话当前模型及实时采样配置。

已有生命周期约束最高优先：恢复子代理使用原子代理模型；内部复制父上下文的路径使用父模型。工作流创建普通子代理时复用相同解析规则，工作流显式模型参数属于单次启动指定。

`inherit` 在第 2 级直接读取父模型，跳过主模型专属与全局模型配置；`reset` 移除覆盖，恢复当前主模型规则。切主模型立即改变后续 child 默认值，临时 set 保持。状态仅描述普通 `general-purpose` 默认选择。

状态新增可选 `parentModelId`、`parentConfiguredModel`，分别显示当前父模型及其专属配置；`configuredModel` 保持全局值。`modelSource="parent_model_config"` 的 UI 中文为「主模型专属配置」。

## 推理强度配置规则

新增 `[subagent] reasoning_effort` 可选字符串，复用现有 `ReasoningEffort` 解析。合法档位为 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`，最终可用档位由目标模型决定。空白表示未设置，非法值明确告警并回退，保留其他有效子代理配置。

普通子代理的推理强度从高到低：

1. 单次启动显式指定的 `reasoning_effort`。
2. `/subagent-model` 临时推理强度（最终模型与临时目标相符时）。
3. 角色或 persona 的推理强度。
4. 新增 `[subagent] reasoning_effort`。
5. agent 定义文件中的 effort。
6. 已选中模型的基础采样配置：继承父模型时使用父会话当前值；指定模型时使用该模型默认值。

在模型解析完成后独立应用推理强度，并校验目标模型声明的具体档位。目标模型不支持推理强度或指定档位时，告警并沿用基础配置，状态查询展示未应用原因。保持模型 ID 随推理档位变化的现有路由能力。

`/subagent-model` 临时切换模型后，以新模型能力重新检查推理强度；`inherit` 和 `reset` 一并清除临时窗口与推理强度，全局推理强度继续按上述规则解析。状态查询同时显示推理强度配置值、实际默认值、来源及支持情况。命令新增与 /model 相同的可选 window/effort 参数；临时 effort 优先于角色和配置默认，单次启动显式 effort 仍最高优先。临时窗口和 effort 仅对最终采用该临时目标模型的子代理应用。inherit/reset 一并清除临时窗口和 effort。

## 参数及生效范围

- 全局 `model` 使用已配置或已加载目录中的模型 ID；省略或空白字符串表示未设置统一默认值，在正常配置加载时生效。
- 全局默认沿用模型目录解析和所选模型自身的上游、接口、认证与能力配置。
- 无法解析的静态配置沿用现有覆盖的告警及逐级回退行为；查询显示无效配置值和实际回退结果。
- 命令参数补全提供已加载可选模型及 `status`、`inherit`、`reset`。控制词为保留字。
- 模型 ID 优先精确解析，显示名称沿用现有匹配方式。未知单个 ID 复用 /model 的上游发现，优先当前连接，再查询其他已配置可选连接；来源鉴权、顺序、超时及策略校验保持一致。发现成功仅注册临时目录并更新子代理选择；失败保留原设置。未知模型带参数与 /model 相同需先发现，再配置其已声明支持的参数。
- 临时选择按父会话隔离，普通主模型切换保留临时指定；`inherit` 动态跟随主模型。
- 进程重启或会话重新加载后恢复配置规则。

新增 E2E profile/scenario：

- `parent-model-selection`：parent→temporary、alternate→plain，目录键与线上模型名不同，双父会话独立且使用目标凭据。
- `parent-model-only/fallback`：只选 model、不新增 effort；省略/空白回退 global，无效目标告警回退且不触发发现。
- `parent-model-lifecycle`：切主模型、临时 set 保持、inherit 跳过配置、reset 恢复当前主模型规则，单次显式优先。
- `parent-model-discovery`：发现模型自身无配置时回退 global，不借用上游来源字段。
- `legacy-section/mixed-sections`：旧表读取、新旧同键单数优先，旧表独有字段保留。

各场景同时检查 `configuredModel` 保持全局值、`parentModelId/parentConfiguredModel` 随当前父模型变化，以及实际 child 的 API、认证、effort 和窗口。旧命令前端兼容与构建、E2E 实际运行由主代理负责；本次文档/脚本任务不运行这些产物。保留 Release 增量缓存及永久 Windows protoc 环境。
