# grok 用户提示词变换钩子（UserPromptTransform）实现计划

> 日期：2026-08-13
> 目标：为 grok 增加一个 **opencode `messages.transform` 等价物**——`UserPromptTransform` 消息变换钩子，
> 使 vision-attachment-bridge 这类"消息发送前强制注入"插件能以 grok 插件（声明式 hooks + 任意语言脚本）方式实现。

## 背景

- opencode-vision-lite 由两部分组成：**vision MCP server**（Go，已通过 `[mcp_servers.opencode-vision-lite]`
  接入 grok，3 个工具可用）与 **attachment-bridge 插件**（TS，依赖 opencode 专有钩子
  `experimental.chat.messages.transform`，grok 无等价物）。
- grok 现有 hooks 只有三种门：`Observe`（输出忽略）、`Tool`（可 deny）、`Stop`（可 block），
  **没有"消息发送前变换"能力**；`UserPromptSubmit` 为 observe-only，输入仅 prompt 文本，无法注入。
- 因此需要为 hooks 系统新增第四种门：**`Transform`**。

## 设计

### 事件定义

| 项 | 值 |
|---|---|
| 事件名 | `UserPromptTransform`（别名：`user_prompt_transform` / `userPromptTransform`） |
| GateKind | `Transform`（新增） |
| MatcherPolicy | `Ignored`（与 `UserPromptSubmit` 一致，fire-all） |
| hub_forward | `true`（通知 hub/client hooks，observe 语义） |
| 输入 payload | `{ prompt: Option<String> }`（完整用户消息文本，含 `<image_files>` 图片路径块） |
| 输出协议 | stdout JSON `{"text": "..."}` 替换用户消息；空/无输出/失败 = 保持原消息（fail-open） |

### 钩子链语义

- 多个匹配 hook **按序链式应用**：每个 hook 收到前序输出，可再次替换。
- 任一 hook 失败（非零退出码、超时、输出非法 JSON、text 为空）均 fail-open，保持当前文本，
  与 grok hooks 既有安全哲学一致。
- 无匹配 hook 或全部未变换时返回 `None`，调用方原样使用原消息。

### 触发时机

`turn.rs` 中 `persist_and_prepend_image_files`（已注入 `<image_files>` 块）**之后**、
`push_user_message`（消息进会话）**之前**调用，返回文本替换 `user_message`。

## 风险与兼容

- 新事件不破坏既有 hook 文件（未知事件名按现有逻辑跳过）；旧版本 grok 读含 `UserPromptTransform`
  的 hooks.json 会跳过该事件（提示 unknown event），行为安全。
- 插件信任机制自动覆盖：未信任插件的 hooks 保持 blocked，无需额外处理。
