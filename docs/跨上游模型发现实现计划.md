# 跨上游模型发现实现计划

## 目标与规则

- 本地目录未命中后优先查询当前上游，命中直接切换。
- 当前上游未命中或请求失败后，查询其他已配置且可选的连接；排除隐藏、禁用和不可选来源。
- 按完整连接信息去重，包含地址、协议、认证、请求头、查询参数及证书；模型名称和能力不参与去重。同地址的不同凭据独立处理。
- 回退最多并发 4 个请求，沿用单来源超时，回退阶段总时限 25 秒。
- 当前上游命中直接使用；回退有多个命中时按本地配置顺序选择第一个，响应快慢不改变选择顺序。某个来源失败不阻止其他来源成功；全部未命中、全部失败或总超时保持原模型并说明原因。
- 来源错误提示显示脱敏后的上游地址，去除内嵌凭据、查询参数和片段，便于识别实际服务。相同地址的不同凭据继续分别查询，避免漏掉不同密钥可访问的模型。
- 各上游使用自身凭据，保留管理策略、模型选择权限、来源指纹及会话并发校验。
- 临时模型继续使用视觉关闭、256000 上下文、无思考参数，不保存为默认配置。

## 修改范围

- `handlers/model_discovery.rs`：单来源查询、连接摘要、回退调度与结果判定。
- `tools/test-model-discovery.py`：多上游本地端到端测试，覆盖当前优先、未命中/HTTP 错误回退、连接去重、同地址不同凭据、歧义、失败保持选择及两轮推理。
- `config/reloader.rs`、`extensions/session_admin.rs`：连接模板及认证提供者配置变更纳入热重载，使发现前后来源校验能观察到更新。
- `README.md`、`Agents.md`、原模型发现计划：同步实际行为。
